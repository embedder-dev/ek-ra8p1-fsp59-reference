# EK-RA8P1 r019: first on-target validation

## Scope and preflight

Follow `VALIDATION.md` in order on the attached EK-RA8P1 v1, J-Link OB `001080841014` (SWD), VCOM `/dev/cu.usbmodem0010808410141`, and Analog Discovery 3 `210415BE5124`. The probe's host label is not the target identity. Use the isolated FSP 5.9.0 area and r019 (`30448d7`); installed-pack and extracted-support checks already passed with `embedder e2 packs verify --fsp 5.9.0 --manifest packs/r019`. Recheck with `--project` after generation. No baseline verification, pack reinstall, pin-model edits, or push. No board operations before approval.

Generate one bare-metal FLAT GNU project for CPU0/CM85 with `embedder e2`, and at most one preceding-project-linked CM33 project if CPU1 is reached. Reuse the projects across stages, generating actual FSP instances and changing only fixture application/configuration. Use the EASE harness only for capabilities e2 cannot cover. Keep scripts, logs, configs, hashes, maps, and captures under `validation/ek-ra8p1/` or `.embedder/hardware/` as appropriate; keep scratch in the workspace or `$TMPDIR` and prune only disposable build outputs.

## Non-negotiable write gates

* **Scratch range for approval:** **`0x0207F800–0x0207FFFF`** **inclusive** (equivalently `[0x0207F800, 0x02080000)`). It is one aligned 2 KiB `r_mram` logical erase block at the end of the CPU0 allocation, below CPU1 at `0x02080000`. Reserve it in the fixture and enforce the exclusion in every link/map and programming-image check, including initialized-data and RAM-code load addresses. Set the generated MRAM write window to those exact bounds and disable extra commands. No alias is an additional permitted range.

* CPU0 download data must be in `[0x02000000, 0x0207F800)`; optional CPU1 data must be in `[0x02080000, 0x02100000)`. Review generated startup and launch behavior. Audit every file-backed ELF load range and loadable section, including its physical load address, rather than just `.text`. Derive a sparse app-only S-record from the fresh ELF; explicitly exclude known option payloads, then independently parse/check the exact S-record byte ranges and checksums against the permitted ranges and ELF. Reject unknown sections/mappings, unexpected aliases, or loader erase behavior that cannot be confined to application code. Hash the ELF and the actual download artifact immediately before each flash and record J-Link verification/readback. **Never feed an option-bearing ELF to a programmer** or use an option-memory override, mass erase, unlock, bank swap, or recovery path that changes protection. No writes to OFS, ID code, security/TrustZone boundaries, DLM, or external storage.

* Use server-arbitrated hardware tools. Record core/reset/halt state before every download; perform and confirm a controlled reset/halt before loading and capture UART from before reset/run where supported. Attach full ELF symbols only, without loading, for diagnosis. CPU1 stays inactive through the mandatory tests. Before bench work, verify providers and port identities, common ground, no display/other driver on the shared header pins, and AD3 digital capture input-only. Keep W1/W2, V+/V−, pattern outputs, and static-I/O outputs off. Do not rewire or change switches without confirmation.

## Ordered tests and evidence

1. **Probe and image.** Connect without programming to `R7KA8P1KF_CPU0`; capture the J-Link target report, hardware chip/part identification where exposed by documented read-only registers, and CPUID for Cortex-M85. Record voltage and reset/halt state. Validate candidate source ownership, selected part/core/toolchain/launch, fresh build, and the programming artifact before proceeding. Do not infer chip identity from a requested device string alone.
2. **CPU0 boot and clocks.** Use generated `r_sci_b_uart` on **SCI8, PD02 TXD8 / PD03 RXD8**, at 115200 8N1. The candidate board profile selects SCI8 and the EK v1 manual Table 13 confirms PD02/PD03 are wired to VCOM. Record a build-tagged boot line from `hal_entry`. Save raw source, PLL if relevant, divider and stability registers and independently decode expected vs live ICLK, PCLKs and MRAM interface/peripheral clocks. Confirm generated pin/pad configuration. Capture all 16 AD3 digital inputs while firmware toggles **P514, P111, P806, P807** individually in labeled windows, with the other pins stationary; save the one-to-one DIO mapping. Use one mapped pin for a GPT interrupt toggle every 10 ms (20 ms rising-edge period); report expected from timer counts/prescaler and documented PCLKD, and measured period over multiple cycles with sample rate and a 1% functional bound.
3. **DAC0 → AN001.** The EK v1 manual Table 20 lists **J19-5/A4/P014/DA0 → 1 kΩ → J19-1/A0/P001/AN001**. Cross-check the board profile/fixture-generated pins against the unchanged RA8P1 pin model (`p014.dac120.da0`, `p001.adc0.an001`) and confirm board routing and reference configuration before enabling the DAC. These J19 pins are not marked as SW4-4 muxed in Table 20; do not change the switch by assumption. Keep P001 high-impedance/analog-only from startup onward. Use generated `r_dac_b` and `r_adc_b`, ADC0 channel 1, settled 12-bit steps (nominally 0/1024/2048/3072/4095, subject to documented safe output/input limits) and a slow ascending ramp. Log command, expected code from the selected reference/transfer functions, repeated readings, signed error and ramp trend. Set a functional tolerance before collecting data (nominal ±2% of full scale, with documented endpoint limits), not an accuracy spec. AD3 scope inputs are disconnected; this is a functional loopback, not a voltage measurement.
4. **`r_cgc`.** Use `R_CGC_SystemClockGet/Set` to change one documented legal divider and back: PCLKD `/1 → /2 → /1` at the default 24 MHz crystal, with PCLKA still `/2` and other clocks unchanged. Verify the manual's clock constraints against live configuration before the change. Keep GPT prescaler and count fixed: expect about 20 → 40 → 20 ms on AD3. Drain UART first; prove framed messages at each stable configuration and record SCI clock selection/baud registers and the before/changed/restored clock values. This tests a reversible divider transition, not PLL switching.
5. **`r_wdt`, only if safe.** Read the effective WDT0 start mode and debugger stop/reset-mask state; require compatible register-start configuration without writing OFS or changing security. Use one-shot, explicitly armed `R_WDT_Open/Refresh` in reset mode; choose an interval inside the refresh window with synchronization margin. Prove that the heartbeat survives several calculated timeouts with refresh, then stop after a timestamped marker. Collect free-running timing and the documented WDT0 reset-cause flag before startup clears it. Recover to an unarmed boot with a working console. Do not run this if option settings, debug behavior, or recovery cannot be established safely; record the reason.
6. **`r_mram`.** Before arming, verify the exact reserved block is readable, unused by either image or any existing application data, and unprotected; snapshot it and establish a read-only comparison of code MRAM outside the block. If any check is unsafe or ambiguous, do not write. Confirm `.code_in_ram` execution and SRAM source data, interrupt/bus-master exclusion, CPU1 inactive and documented cache/readback handling. Run `Open`, one-block `Erase`, verify all `0xFF`, write a deterministic pattern from SRAM, and compare memory-mapped and debugger readback of the full block. Compare before/after outside-block code MRAM evidence and preserve the original scratch snapshot; leave the qualified scratch block blank after evidence, not a pattern in live code. No erase/write outside the approved scratch range during this test.
7. **CPU1, optional.** After the mandatory sequence, use the generated CPU0 secondary-start path and disjoint audited CM33 image. Prefer a changing CPU1-owned RAM counter, observed by a symbols-only CPU1 attach to `R7KA8P1KF_CPU1`, with CPU1 CPUID and CPU0 still alive. This avoids a new shared-memory ABI or a second UART wiring assignment.
8. **`r_pdm`, optional.** If the documented on-board route can be used as wired, use generated `r_pdm` with P812/P502 (EK manual Table 31 and candidate profile), capture a bounded sample buffer, and save callback/overrun counts and sample statistics showing non-constant data. Mark audio content and electrical PDM signaling unverified; do not add AD3 probes or drive a stimulus electrically.

## Failure and report

At the first failure stop the sequence, retain the failing image/logs, and distinguish a fixture, setup, or tooling issue from a candidate defect. Diagnose with the map/config, UART, debugger and capture; change owning production C/MDF/BSP only for a demonstrated defect, never copied generated driver code. If required, build a new candidate revision and refresh only the isolated install with rollback/inventory, then reverify all three pack layers, rerun affected host tests and clean generated builds, and repeat the failed stage and affected earlier checks before proceeding. If a required safety gate cannot be met, stop at that stage rather than working around it. A watchdog deliberately skipped for safety does not prevent the subsequent scratch test if the board is confirmed recovered and safe.

Finish with the single `VALIDATION.md` table: **CPU0 BSP, CPU1 BSP, EK-RA8P1 board, r\_cgc, r\_dac\_b, r\_adc\_b, r\_wdt, r\_mram, r\_pdm**; columns **test run, expected, observed, evidence, status** (`passed`, `failed`, `blocked`, `not run`). Follow it with fixed defects and file/line, unfixed defects, and what was untested and why. Link evidence paths; host builds and tests do not count as physical passes.

No reference firmware is ported. Compared with the repo bench guide, use AD3 digital capture instead of Saleae, discover its DIO mapping rather than copying channel numbers, omit the scope and proposed PDM probes, and keep the resistor loopback and pin roles as documented. The clock transition intentionally uses a legal divider change rather than the example source switch to keep the console clock stable.
