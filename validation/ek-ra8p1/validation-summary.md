# RA8P1 / EK-RA8P1 validation summary

**Bench date:** November 24, 2026. **Platform:** one EK-RA8P1 v1, `R7KA8P1KFLCAC` Rev. A, at ambient conditions; custom FSP 5.9.0; GNU bare-metal Flat fixtures; on-board J-Link, SCI8 VCOM, and an input-only Analog Discovery 3 (AD3).

**Verdict: r021 passed the bounded bench qualification, not production qualification.** r021 passed CPU0 boot/reset, CPU1 start, board GPIO/GPT timing, PCLKD switching, WDT0 recovery, and concurrent MIC1 acquisition. DAC/ADC and bounded MRAM write/erase passed on **r020 only**. The full regression gate is still open. See the [formal bench report](results.md) and [original validation procedure](../../VALIDATION.md). This summary groups repeated runs by test and includes the failures that affected the qualification verdict; it does not count retries as independent coverage.

## What the failed runs changed

- **Production — GPT clock selection (r019 → r020).** The 57.250 ms measurement exposed that the RA8P1 BSP metadata did not select PCLKD for GPT when dedicated GPTCLK was disabled. The [BSP MDF fix and retest](results.md#fixed-defects) restored the intended timer source. A build-only test hadn't caught this.
- **Production — Rev. A clock startup (r020 → r021).** With application bytes verified, r020 could boot with the wrong divider (`0x10000000` instead of `0x00001110`) or fault before application start when run at full speed. The [fault trace](evidence/r020-unpaused-bus-fault.log), [pre-transition cache state](evidence/r020-pre-vscr-cache-state.log), and hardware manual identified a voltage-scaling transition with the M85 caches still enabled and active. r021 disables and deactivates them for that transition, then restores the prior state. [ELF placement checks](evidence/r021-startup-placements.log) verified code MRAM and system SRAM reset-stack placement on the three r021 fixtures; the reset tests then passed without pausing startup.
- **Fixture and automation failures, not confirmed driver defects.** The analog fixture's initial 1 KiB stack overflow was resolved by a 4 KiB generated stack. MRAM was initially withheld because the scratch block contained unknown data, then armed only after authorization and after resolving two no-write preflight refusals, including a comparison of reserved `MREZS` bits. The [first paired PDM soak](evidence/pdm-soak-1795568564965710000-rtlodk03.jsonl) timed out on UART stop matching even though `ACK clocks` was in the log; a corrected parser passed. The [first r021 WDT attempt](evidence/wdt-uart-1795569573891169000.json) didn't exercise the watchdog because that image didn't expose the arm command; the [WDT-enabled rebuild](evidence/r021-wdt-verified-build.log) and retest did. See [analog fault artifacts](evidence/analog-stack-fault/) and [MRAM preflight notes](mram-notes.md).

## What remains before production sign-off

1. **Close the exact-release regression gate.** Restore the [missing generated controls, historical pack/fixture revisions, and validation specs/apps](evidence/host-suite-recovered.log#L1529). Rerun the full suite on the release candidate and resolve or document the `r_acmphs`/`r_ioport` warnings. Don't substitute a generated header that differs from the frozen control.
2. **Repeat DAC/ADC and bounded MRAM on r021.** Keep the existing application-only download and scratch-only write limits. If MRAM retention is a release requirement, add a controlled, documented power-cycle readback before cleanup.
3. **Test the intended production configurations and operating range.** Exercise shipping clock profiles, including PLL/high-speed if used, debugger-free resets with first-output capture, and the actual two-core workload and recovery paths. Use multiple boards and all shipping silicon revisions across the specified voltage and temperature range.
4. **Qualify only what will be advertised or shipped.** Commercial compiler runtime, calibrated analog, continuous audio, low-power wake, and TrustZone/protection behavior were not qualified by this bench. Treat irreversible provisioning and protection tests as a separate qualification with explicitly authorized hardware.
